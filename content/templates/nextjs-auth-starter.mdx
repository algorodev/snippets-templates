A ready-to-go authentication setup using Auth.js v5 (NextAuth) with the App Router. Covers OAuth sign-in, email magic links, session access in both Server and Client Components, and route protection via middleware.

## Usage

```typescript
// auth.ts  — central Auth.js config
import NextAuth from "next-auth";
import GitHub from "next-auth/providers/github";
import Google from "next-auth/providers/google";
import Resend from "next-auth/providers/resend";
import { PrismaAdapter } from "@auth/prisma-adapter";
import { prisma } from "@/lib/prisma";

export const { handlers, signIn, signOut, auth } = NextAuth({
  adapter: PrismaAdapter(prisma),
  providers: [
    GitHub({
      clientId: process.env.AUTH_GITHUB_ID!,
      clientSecret: process.env.AUTH_GITHUB_SECRET!,
    }),
    Google({
      clientId: process.env.AUTH_GOOGLE_ID!,
      clientSecret: process.env.AUTH_GOOGLE_SECRET!,
    }),
    Resend({
      apiKey: process.env.AUTH_RESEND_KEY!,
      from: "noreply@yourdomain.com",
    }),
  ],
  pages: {
    signIn: "/login",
    error: "/auth/error",
    verifyRequest: "/auth/verify",
  },
  callbacks: {
    session({ session, user }) {
      session.user.id = user.id;
      return session;
    },
  },
});
```

```typescript
// middleware.ts — protect routes
import { auth } from "@/auth";
import { NextResponse } from "next/server";

export default auth((req) => {
  const isLoggedIn = !!req.auth;
  const isOnDashboard = req.nextUrl.pathname.startsWith("/dashboard");
  const isOnAuth = req.nextUrl.pathname.startsWith("/login");

  if (isOnDashboard && !isLoggedIn) {
    return NextResponse.redirect(new URL("/login", req.url));
  }

  if (isOnAuth && isLoggedIn) {
    return NextResponse.redirect(new URL("/dashboard", req.url));
  }

  return NextResponse.next();
});

export const config = {
  matcher: ["/dashboard/:path*", "/login"],
};
```

import { auth } from "@/auth";

export default async function DashboardPage() {

**Adding a new OAuth provider:**

```typescript
// auth.ts
import Twitter from "next-auth/providers/twitter";

providers: [
  // ...existing providers
  Twitter({
    clientId: process.env.AUTH_TWITTER_ID!,
    clientSecret: process.env.AUTH_TWITTER_SECRET!,
  }),
],
```

**Accessing session on the client:**

```typescript
"use client";
import { useSession } from "next-auth/react";

export function UserAvatar() {
  const { data: session, status } = useSession();
  if (status === "loading") return <div className="h-8 w-8 animate-pulse rounded-full bg-gray-200" />;
  if (!session) return null;
  return <img src={session.user?.image ?? ""} alt="" className="h-8 w-8 rounded-full" />;
}
```

## Notes

- The `auth()` helper works in Server Components, Route Handlers, and middleware — do not use `getServerSession` (NextAuth v4 API).
- `signIn()` and `signOut()` from `"next-auth"` are for Server Actions; import from `"next-auth/react"` for Client Components.
- The Prisma adapter persists sessions and accounts to your database automatically — required for magic links.
- Wrap your root layout (or a subtree) in `<SessionProvider>` from `next-auth/react` only when you need `useSession` on the client.

## README

### What this includes

- Auth.js v5 (NextAuth) configured for the App Router
- GitHub and Google OAuth sign-in
- Email magic links via Resend
- Prisma adapter for session/account persistence
- Middleware-based route protection
- `auth()` helper for Server Components and Route Handlers
- Sign-in page with OAuth buttons and magic link form
- Sign-out support in both Server Actions and Client Components
- Error and verify-request pages

### Prerequisites

- Node.js 18+
- A PostgreSQL database (Neon, Supabase, Railway, etc.)
- OAuth app credentials from GitHub and/or Google
- A Resend account and API key for magic links

### Create this template

```bash
npx create-next-app@latest my-app --typescript --tailwind --eslint --app
cd my-app

# Auth.js v5 + Prisma adapter
npm install next-auth@beta @auth/prisma-adapter

# Prisma ORM
npm install prisma @prisma/client
npx prisma init --datasource-provider postgresql

# Apply Auth.js schema to Prisma
# Copy the Auth.js Prisma schema from:
# https://authjs.dev/getting-started/adapters/prisma
# into prisma/schema.prisma, then:
npx prisma db push

# Create auth config
touch auth.ts

# Create API route handler
mkdir -p app/api/auth/\[...nextauth\]
touch app/api/auth/\[...nextauth\]/route.ts

# Create middleware
touch middleware.ts

# Create pages
mkdir -p app/login app/dashboard app/auth/error app/auth/verify
touch app/login/page.tsx app/dashboard/page.tsx

cp .env.example .env.local
# Fill in AUTH_SECRET, AUTH_GITHUB_ID, AUTH_GITHUB_SECRET,
# AUTH_GOOGLE_ID, AUTH_GOOGLE_SECRET, AUTH_RESEND_KEY, DATABASE_URL
npm run dev
```

### Project structure

```
auth.ts                         # Central Auth.js config (providers, adapter, callbacks)
middleware.ts                   # Route protection logic
app/
  api/auth/[...nextauth]/
    route.ts                    # Auth.js route handler
  login/
    page.tsx                    # Sign-in page (OAuth + magic link)
  dashboard/
    page.tsx                    # Protected page using auth()
  auth/
    error/page.tsx              # Auth error display
    verify/page.tsx             # "Check your email" page
components/
  sign-out-button.tsx           # Client Component sign-out
lib/
  prisma.ts                     # Prisma client singleton
prisma/
  schema.prisma                 # Auth.js schema + your models
.env.local                      # Secrets (never commit)
```

### First things to customize

- **`auth.ts`** — add or remove OAuth providers; update the `from` address for magic link emails
- **`.env.local`** — fill in `AUTH_SECRET` (generate with `npx auth secret`), OAuth credentials, `AUTH_RESEND_KEY`, and `DATABASE_URL`
- **`middleware.ts`** — update the `matcher` array to protect additional route segments
- **`app/login/page.tsx`** — adjust branding, copy, and which providers to show
- **`prisma/schema.prisma`** — add your own models after the Auth.js tables
- **`auth.ts` callbacks** — extend the session object with additional user fields (e.g., `role`, `plan`)
