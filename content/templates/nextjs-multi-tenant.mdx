A production-grade multi-tenant architecture where each tenant gets their own subdomain (`acme.yourapp.com`), isolated data, and customizable branding — all routed through a single Next.js deployment.

## Usage

```typescript
// middleware.ts — subdomain-based tenant routing
import { NextRequest, NextResponse } from "next/server";

const ROOT_DOMAIN = process.env.NEXT_PUBLIC_ROOT_DOMAIN!; // e.g. "yourapp.com"

export function middleware(req: NextRequest) {
  const url = req.nextUrl;
  const hostname = req.headers.get("host") ?? "";

  // Strip port for local dev (localhost:3000 → localhost)
  const currentHost =
    process.env.NODE_ENV === "development"
      ? hostname.replace(`.localhost:3000`, "")
      : hostname.replace(`.${ROOT_DOMAIN}`, "");

  // Pass-through for the root domain and API routes
  if (
    currentHost === ROOT_DOMAIN ||
    currentHost === "www" ||
    url.pathname.startsWith("/api/") ||
    url.pathname.startsWith("/_next/")
  ) {
    return NextResponse.next();
  }

  // Rewrite to /[tenant]/... without changing the URL shown to the user
  return NextResponse.rewrite(
    new URL(`/${currentHost}${url.pathname}`, req.url)
  );
}

export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"],
};
```

```typescript
// lib/tenant.ts — resolve tenant from current request
import { headers } from "next/headers";
import { cache } from "react";
import { prisma } from "@/lib/prisma";

export const getTenant = cache(async () => {
  const headersList = await headers();
  const host = headersList.get("host") ?? "";
  const rootDomain = process.env.NEXT_PUBLIC_ROOT_DOMAIN!;

  const subdomain =
    process.env.NODE_ENV === "development"
      ? host.replace(".localhost:3000", "")
      : host.replace(`.${rootDomain}`, "");

  if (!subdomain || subdomain === rootDomain) return null;

  return prisma.tenant.findUnique({
    where: { subdomain },
    include: { settings: true },
  });
});
```

```typescript
export default async function TenantLayout({
  children,
  params,
}: {
  children: React.ReactNode;
```

```typescript
import { getTenant } from "@/lib/tenant";
import { auth } from "@/auth";
import { redirect } from "next/navigation";
import { notFound } from "next/navigation";

export default async function TenantDashboard() {

  );
}
```

```typescript
"use client";

import { useState } from "react";
import { useRouter } from "next/navigation";

export default function OnboardingPage() {
  const router = useRouter();
  const [subdomain, setSubdomain] = useState("");
  const [name, setName] = useState("");
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState("");

  const rootDomain = process.env.NEXT_PUBLIC_ROOT_DOMAIN!;

  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    setLoading(true);
    setError("");

    const res = await fetch("/api/tenants", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ name, subdomain }),

        ? `http://${subdomain}.localhost:3000`

    <main className="flex min-h-screen flex-col items-center justify-center p-4">

            <label className="block text-sm font-medium text-gray-700 dark:text-gray-300">
```

```typescript
// app/api/tenants/route.ts — create tenant API endpoint
import { NextRequest, NextResponse } from "next/server";
import { auth } from "@/auth";
import { prisma } from "@/lib/prisma";
import { z } from "zod";

const createTenantSchema = z.object({
  name: z.string().min(2).max(64),
  subdomain: z
    .string()
    .min(3)
    .max(32)
    .regex(/^[a-z0-9-]+$/, "Only lowercase letters, numbers, and hyphens"),
});

const RESERVED = new Set(["www", "api", "app", "admin", "mail", "dashboard"]);

export async function POST(req: NextRequest) {
  const session = await auth();
  if (!session?.user?.id) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  const body = await req.json();
  const result = createTenantSchema.safeParse(body);
  if (!result.success) {
    return NextResponse.json(
      { error: result.error.issues[0].message },
      { status: 400 }
    );
  }

  const { name, subdomain } = result.data;

  if (RESERVED.has(subdomain)) {
    return NextResponse.json(
      { error: "That subdomain is reserved." },
      { status: 400 }
    );
  }

  const existing = await prisma.tenant.findUnique({ where: { subdomain } });
  if (existing) {
    return NextResponse.json(
      { error: "That subdomain is already taken." },
      { status: 409 }
    );
  }

  const tenant = await prisma.tenant.create({
    data: {
      name,
      subdomain,
      settings: { create: {} },
      users: {
        create: {
          userId: session.user.id,
          role: "OWNER",
        },
      },
    },
  });

  return NextResponse.json(tenant, { status: 201 });
}
```

## How it works

1. **Middleware intercepts every request.** It reads the subdomain from `Host`, strips the root domain, and rewrites the path from `/dashboard` to `/acme/dashboard` — invisibly. Next.js then resolves `app/[tenant]/dashboard/page.tsx`.
2. **`getTenant()`** is a cached async function that reads the rewritten path segment (or `Host` header) and fetches the matching tenant from the database. Call it in any Server Component or Route Handler.
3. **Tenant layout** injects per-tenant CSS variables (brand color, logo) so every subdomain can look distinct without separate deployments.
4. **Onboarding flow** creates the tenant record, a `TenantSettings` row, and the first `TenantMembership` (role: `OWNER`) in a single Prisma transaction.

## Notes

- For custom domain support (`customer.com` → your app), point the customer's DNS CNAME to your deployment and handle the `Host` header in middleware the same way.
- On Vercel, add a wildcard domain (`*.yourapp.com`) in the project settings — Vercel routes all subdomains to the same deployment automatically.
- Use `getTenant()` with React `cache()` so repeated calls within a single request are deduplicated.
- Row-level security: always filter Prisma queries by `tenantId` — never fetch cross-tenant data.

## README

### What this includes

- Subdomain-based tenant routing via Next.js middleware (no separate apps)
- `getTenant()` helper — resolves tenant from `Host` header in any Server Component
- Per-tenant branding (logo, primary color) via CSS custom properties
- Tenant creation API with Zod validation and reserved subdomain list
- Onboarding page to create a workspace and redirect to the new subdomain
- Prisma schema with `Tenant`, `TenantSettings`, `TenantMembership` models
- Role system: `OWNER`, `ADMIN`, `MEMBER`
- Plan enum: `FREE`, `PRO`, `ENTERPRISE` with billing hook placeholders

### Prerequisites

- Node.js 18+
- A PostgreSQL database
- A domain with wildcard DNS (`*.yourapp.com → your server`)
- Auth.js v5 configured (see the Next.js Auth Starter template)

### First things to customize

- **`.env.local`** — set `NEXT_PUBLIC_ROOT_DOMAIN` to your actual domain
- **`prisma/schema.prisma`** — add tenant-scoped resource models (e.g., `Project`, `Post`) with a `tenantId` foreign key
- **`lib/tenant.ts`** — extend the `getTenant()` query to include the relations your layouts and pages need
- **`app/[tenant]/layout.tsx`** — update the navigation links and branding to match your product
- **`middleware.ts`** — add custom domain support by checking `req.headers.get("host")` against a `customDomain` database lookup
- **`app/api/billing/webhook/route.ts`** — wire your Stripe webhook to update `tenant.plan` on subscription events
