A content-first blog using Astro's type-safe content collections, MDX authoring, and Tailwind CSS — ships zero client-side JavaScript by default and generates a valid RSS feed and sitemap at build time.

## Usage

```typescript
// src/content/config.ts
import { defineCollection, z } from 'astro:content'

const blog = defineCollection({
  type: 'content',
  schema: z.object({
    title: z.string(),
    description: z.string(),
    pubDate: z.coerce.date(),
    updatedDate: z.coerce.date().optional(),
    tags: z.array(z.string()).default([]),
    draft: z.boolean().default(false),
  }),
})

export const collections = { blog }
```

```typescript
// src/pages/rss.xml.ts
import rss from '@astrojs/rss'
import { getCollection } from 'astro:content'
import type { APIContext } from 'astro'

export async function GET(context: APIContext) {
  const posts = await getCollection('blog', ({ data }) => !data.draft)
  const sorted = posts.sort(
    (a, b) => b.data.pubDate.getTime() - a.data.pubDate.getTime()
  )

  return rss({
    title: 'My Blog',
    description: 'The latest posts from my blog.',
    site: context.site!,
    items: sorted.map((post) => ({
      title: post.data.title,
      description: post.data.description,
      pubDate: post.data.pubDate,
      link: `/blog/${post.slug}/`,
    })),
    customData: '<language>en-us</language>',
  })
}
```

## Notes

Astro renders pages as static HTML at build time. If you need client-side interactivity, add an `client:load` (or `client:visible`) directive to any framework component — React, Svelte, Vue, and Solid are all supported via official integrations.

## README

### What this includes

- **Content Collections** — type-safe blog posts with Zod schema validation on frontmatter
- **MDX support** — use JSX components inside `.mdx` post files
- **Zero JS by default** — pages ship as plain HTML; hydration is opt-in per component
- **Tailwind CSS** — utility-first styling via `@astrojs/tailwind`
- **RSS feed** — `/rss.xml` generated via `@astrojs/rss`
- **Sitemap** — auto-generated `sitemap-index.xml` via `@astrojs/sitemap`
- **Tag pages** — `/blog/tags/[tag]` listing posts filtered by tag
- **Draft support** — posts with `draft: true` are excluded from production builds

### Prerequisites

- Node.js 20.9 or later
- npm, pnpm, yarn, or bun

### Create this template

```bash
# 1. Scaffold the official Astro blog starter
npm create astro@latest my-blog -- --template blog --typescript strict --install --git

cd my-blog

# 2. Add Tailwind CSS integration
npx astro add tailwind --yes

# 3. Add MDX integration
npx astro add mdx --yes

# 4. Add sitemap integration
npx astro add sitemap --yes

# 5. Install RSS helper
npm install @astrojs/rss

# 6. Start the dev server
npm run dev
```

### Project structure

```
my-blog/
  src/
    content/
      config.ts               # Collection schema definitions
      blog/
        hello-world.mdx       # MDX post files live here
    layouts/
      BaseLayout.astro        # HTML shell with <head> and nav
      PostLayout.astro        # Prose wrapper for individual posts
    pages/
      index.astro             # Homepage
      blog/
        index.astro           # Post listing
        [slug].astro          # Individual post page
        tags/
          [tag].astro         # Posts filtered by tag
      rss.xml.ts              # RSS feed endpoint
    components/
      PostCard.astro          # Post preview card
      FormattedDate.astro     # Locale-aware date display
      Header.astro
      Footer.astro
  public/
  astro.config.mjs
  tailwind.config.mjs
  tsconfig.json
```

### First things to customize

- `astro.config.mjs` — set `site: 'https://yourdomain.com'` (required for RSS and sitemap)
- `src/layouts/BaseLayout.astro` — update the site name, nav links, and `<head>` metadata
- `src/pages/rss.xml.ts` — replace the hardcoded feed `title` and `description`
- `src/content/config.ts` — extend the schema with any extra frontmatter fields you need
- `tailwind.config.mjs` — add brand colors, custom fonts, and typography overrides
- `src/content/blog/` — delete the sample posts and add your own `.mdx` files
