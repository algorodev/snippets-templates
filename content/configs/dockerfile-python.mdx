A multi-stage Dockerfile that uses `uv` to install dependencies in a build stage, then copies only the installed packages into a slim runtime image. A non-root user is created so the container does not run as root in production.

## Usage

```dockerfile
# syntax=docker/dockerfile:1

# ── Build stage ──────────────────────────────────────────────────────────────
FROM python:3.12-slim AS builder

# Install uv (fast Python package installer / resolver)
COPY --from=ghcr.io/astral-sh/uv:latest /uv /usr/local/bin/uv

WORKDIR /app

# Copy dependency manifests first so this layer is cached when only code changes
COPY pyproject.toml uv.lock ./

# Install dependencies into /app/.venv — no editable install of the project itself
RUN uv sync --frozen --no-install-project

# Copy source code after dependencies to maximise cache reuse
COPY . .

# Install the project itself (without re-solving dependencies)
RUN uv sync --frozen

# ── Runtime stage ─────────────────────────────────────────────────────────────
FROM python:3.12-slim AS runtime

# Create a non-root user and group
RUN groupadd --system appgroup && \
    useradd --system --gid appgroup --no-create-home appuser

WORKDIR /app

# Copy the fully-built virtual environment from the builder stage
COPY --from=builder --chown=appuser:appgroup /app/.venv /app/.venv
# Copy application source
COPY --from=builder --chown=appuser:appgroup /app/src /app/src

# Ensure the venv's binaries are on PATH
ENV PATH="/app/.venv/bin:$PATH" \
    PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1

USER appuser

EXPOSE 8000

# Replace with your actual entry point
CMD ["python", "-m", "src.main"]
```

## How it works

The build is split into two stages to keep the final image as small as possible:

1. **Builder stage** — installs `uv`, resolves and installs all dependencies into a virtual environment at `/app/.venv`, then installs the project itself. All build tooling stays in this stage.
2. **Runtime stage** — starts from a fresh `python:3.12-slim` image and copies only the `.venv` directory and application source from the builder. No compilers or package managers end up in the final image.

The non-root `appuser` is created and used to run the process, which limits the blast radius of any container escape.

## Options

| ARG / ENV | Default | Purpose |
|---|---|---|
| `PYTHONUNBUFFERED` | `1` | Stream stdout/stderr directly (important for log aggregators) |
| `PYTHONDONTWRITEBYTECODE` | `1` | Skip `.pyc` files — saves a few MB in runtime image |
| `PATH` | `.venv/bin` prepended | Activate the virtual environment without sourcing it |

## Notes

- Pin the `uv` image tag (e.g. `ghcr.io/astral-sh/uv:0.4.0`) in production instead of using `latest`.
- If your project uses a `requirements.txt` instead of `pyproject.toml`, replace the `uv sync` commands with `uv pip install --system -r requirements.txt`.
- Add a `.dockerignore` to exclude `__pycache__`, `.venv`, `.git`, and test files from the build context.
