Triggered on every published release, this workflow builds a multi-platform Docker image (`linux/amd64` and `linux/arm64`) and pushes it to Docker Hub with both a versioned tag and a `latest` tag.

## Usage

```yaml
name: Docker Build and Push

on:
  release:
    types: [published]

env:
  REGISTRY: docker.io
  IMAGE_NAME: ${{ github.repository }}

jobs:
  build-and-push:
    name: Build and Push Docker Image
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up QEMU
        uses: docker/setup-qemu-action@v3

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to Docker Hub
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}

      - name: Extract Docker metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}
          tags: |
            type=semver,pattern={{version}}
            type=semver,pattern={{major}}.{{minor}}
            type=raw,value=latest,enable={{is_default_branch}}

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: .
          platforms: linux/amd64,linux/arm64
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

## Options

| Field | Default | Effect |
|-------|---------|--------|
| `on.release.types` | `[published]` | Change to `[created]` to trigger on draft releases too |
| `platforms` | `linux/amd64,linux/arm64` | Remove `linux/arm64` to skip ARM builds and cut build time |
| `cache-from/cache-to` | `type=gha` | GitHub Actions layer cache — keeps re-builds fast |
| `REGISTRY` | `docker.io` | Set to `ghcr.io` for GitHub Container Registry |

## How it works

1. QEMU registers cross-compilation handlers so the runner can build for `arm64` natively without actual ARM hardware.
2. Buildx creates a multi-node builder that produces a single multi-platform manifest.
3. `docker/metadata-action` generates tags from the Git release tag (`v1.2.3` → `1.2.3` and `1.2`), keeping `latest` in sync with the default branch.
4. GitHub Actions cache (`type=gha`) stores Docker layer cache between runs, dramatically reducing build time for unchanged layers.

## Notes

- Add `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` as repository secrets (Settings → Secrets and variables → Actions). Use an access token, not your account password.
- To use GitHub Container Registry instead of Docker Hub, set `REGISTRY: ghcr.io`, remove the Docker Hub login step, and replace it with a login that uses `GITHUB_TOKEN`:
  ```yaml
  - uses: docker/login-action@v3
    with:
      registry: ghcr.io
      username: ${{ github.actor }}
      password: ${{ secrets.GITHUB_TOKEN }}
  ```
- To trigger on every push to `main` instead of releases, replace the `on` block with `on: push: branches: [main]`.
